# Сервис курсов валют

Простое приложение на **Spring Boot 3.5.16, Java 21 и Maven**. REST API возвращает курс между двумя валютами и сконвертированную сумму. Основная валюта хранения — KZT: каждая котировка содержит тенге за единицу валюты. Курсы сохраняются в файловой H2 и обновляются по запросу при отсутствии актуальных данных.

## Запуск

Нужны JDK 21 и Maven 3.6.3 или новее. При первой сборке нужен доступ к Maven Central.

```bash
mvn clean verify
mvn spring-boot:run
```

Или запуск собранного приложения:

```bash
java -jar target/currency-service-0.0.1-SNAPSHOT.jar
```

Первый запрос на конвертацию разных валют заполняет БД из внешнего источника. Приложение создаёт файлы БД в `./data/` относительно текущего каталога; запускайте его из корня проекта. Данные сохраняются после остановки. Для локального запуска не нужны Docker, отдельная БД или API-ключ.

При запуске со старой RUB-схемой `schema.sql` автоматически пересчитывает кеш в KZT и заменяет колонку `rub_per_unit` на `kzt_per_unit`, сохраняя даты. Если в старом наборе нет KZT, кеш очищается и загружается заново при следующей конвертации разных валют. Удалять файл БД вручную не нужно.

Для ручных SQL-проверок доступна встроенная H2 Console: `http://localhost:8080/h2-console`. JDBC URL — `jdbc:h2:file:./data/currency`, пользователь — `sa`, пароль пустой. Дополнительные настройки запуска и отдельный сервер источника не нужны.

```bash
curl -sS -X POST http://localhost:8080/api/v1/conversions \
  -H 'Content-Type: application/json' \
  -d '{"from":"USD","to":"398","amount":100}'
```

`398` — KZT, `840` — USD, `978` — EUR, `643` — RUB. Цифровой код передавайте строкой из трёх цифр: это сохраняет ведущие нули, например `"008"`. Регистр букв и пробелы по краям не имеют значения.

Для проверки без интернета и без заполненной БД:

```bash
curl -sS -X POST http://localhost:8080/api/v1/conversions \
  -H 'Content-Type: application/json' \
  -d '{"from":"USD","to":"840","amount":12.345}'
```

Ответ содержит `rate: 1.0000000000`, `convertedAmount: 12.35`; обе даты равны `null`, поскольку курс не использовался.

## Настройки

Основные настройки — в [application.yml](src/main/resources/application.yml).

| Переменная окружения | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `SERVER_PORT` | `8080` | Порт REST API |
| `DB_URL` | `jdbc:h2:file:./data/currency` | JDBC URL H2 |
| `DB_USERNAME` | `sa` | Пользователь БД |
| `DB_PASSWORD` | пустая строка | Пароль БД |
| `RATES_PROVIDER_URL` | `https://open.er-api.com/v6/latest/USD` | URL JSON API ExchangeRate-API с базой USD |
| `RATES_ZONE` | `Asia/Almaty` | Часовой пояс календарного дня |
| `RATES_CONNECT_TIMEOUT` | `3s` | Таймаут соединения |
| `RATES_READ_TIMEOUT` | `5s` | Таймаут чтения ответа |

Источник — [Rates By Exchange Rate API](https://www.exchangerate-api.com). Его [публичный endpoint](https://www.exchangerate-api.com/docs/free) работает без API-ключа и обновляет данные раз в сутки. При использовании курсов на страницах приложения нужно разместить ссылку на источник. Прямая проверка:

```bash
curl -i 'https://open.er-api.com/v6/latest/USD'
```

URL другого источника можно задать только при совместимости с JSON ExchangeRate-API и базой USD. Для другого формата нужно реализовать `RatesProvider`. PostgreSQL в текущую сборку не включён.

## Структура кода

`api` принимает и проверяет запросы; `ConversionService` решает, когда обновить курсы; `ConversionCalculator` рассчитывает курс и сумму; `CurrencyResolver` распознаёт ISO-коды; `ExchangeRateApiProvider` обращается к источнику; `ExchangeRateApiParser` проверяет JSON и нормализует котировки в KZT за единицу; `RateRepository` читает и атомарно заменяет данные через `JdbcTemplate`.

Это приложение для одного экземпляра: простой `synchronized` согласует обновление курсов при одновременных запросах внутри процесса. История курсов, комиссии, авторизация, распределённые блокировки и управление курсами через API не входят в задачу.

Тесты используют JUnit 5 и реальные классы расчёта, распознавания валют и разбора JSON. В `ConversionServiceTest` Mockito подменяет репозиторий и источник для проверки кеша, обновления и ошибок; часы фиксированы в Asia/Almaty. Три интеграционных теста запускают H2 в памяти и проверяют новую схему, миграцию RUB → KZT и повторную инициализацию. Всего выполняются 24 проверки. AssertJ, Spring Test и сеть не используются. REST, HTTP-загрузка и транзакции проверяются по ручным тест-кейсам.
