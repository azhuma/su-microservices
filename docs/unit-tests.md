# Юнит-тесты и проверки схемы H2

Запуск: `mvn test` или `mvn clean verify`. Единственная тестовая зависимость — `org.junit.jupiter:junit-jupiter`. Используются `@Test` и проверки из `org.junit.jupiter.api.Assertions`: без Mockito, AssertJ, Spring Test, собственных моков и подмен зависимостей.

Девять юнит-тестов создают настоящие `CurrencyResolver`, `ConversionCalculator`, `ExchangeRateApiParser` и записи `ExchangeRate`. Расчёт и ISO-справочник зависят только от JDK и DTO; JSON-парсер использует рабочую зависимость Jackson. Три дополнительных теста схемы используют настоящую H2 в памяти и `RateRepository`. Spring-контекст и HTTP-клиент не запускаются. Даты передаются как данные, системные часы не используются.

## Почему выбран этот набор

Выбраны независимые правила бизнес-логики, ошибка в которых меняет результат конвертации: распознавание кодов, отказ для неверных кодов, направление деления, тождественное преобразование, округление по валюте и сохранение точности до расчёта суммы. Для каждого правила используются представители входных данных; перебор всех ISO-кодов и повторение одного расчёта с десятками сумм мало добавляют к этим проверкам.

Для ExchangeRate-API проверяются нормализация котировок в KZT и отклонение ошибочного набора. После смены базовой валюты добавлена проверка ответа без RUB: обязательны USD и KZT, RUB — обычная валюта. Парсер доступен без сети и Spring, поэтому его можно проверить реальным JSON без моков.

Переход на KZT меняет схему БД, поэтому три теста выполняют настоящий `schema.sql` в H2: создание новой схемы и чтение/запись, пересчёт старого RUB-кеша и повторный запуск, очистка старого кеша без KZT. Все двенадцать тестов запускаются через `mvn test`.

Набор ограничен выбранным уровнем проверки. HTTP-статусы, Bean Validation, HTTP-загрузка, обновление по запросу и транзакции проверяются по [ручным тест-кейсам](test-cases.md). Запуск JUnit не означает прохождение этих кейсов.

## Набор и связь с ручными кейсами

В `src/test/java/kz/su/currency/service/CurrencyResolverTest.java`:

| Метод | Ручной кейс | Почему создан |
| --- | --- | --- |
| `resolvesSupportedCodeFormats` | TC-01, TC-09 | Буквы, цифры, регистр, пробелы и ведущий ноль — разные особенности входного контракта. Проверяет нормализованные коды, включая `008` → ALL. |
| `rejectsInvalidAndNonMonetaryCodes` | TC-08 | По одному представителю отсутствующего ввода, ошибок формата, неизвестных буквенного/цифрового кодов и немонетарной валюты. Проверяет `IllegalArgumentException`; преобразование в HTTP 400 остаётся ручной проверкой. |

В `src/test/java/kz/su/currency/service/ConversionCalculatorTest.java`:

| Метод | Ручной кейс | Почему создан |
| --- | --- | --- |
| `calculatesCrossReverseAndBaseRates` | TC-01, TC-02 | Прямой и обратный курсы обнаруживают перепутанные числитель и знаменатель; KZT проверяет базовую валюту, RUB — кросс-курс. Также проверяются коды, исходная сумма и перенос дат. |
| `convertsSameCurrencyWithoutRates` | TC-03 | Это отдельная ветка: курс 1, округлённая сумма и null-даты при отсутствии входных котировок. Отсутствие обращений сервиса к БД/источнику проверяется вручную. |
| `roundsHalfUpWithCurrencyFractionDigitsAndAcceptsZero` | TC-04 | JPY, USD и KWD представляют 0, 2 и 3 дробных разряда. Значения на середине различают HALF_UP и HALF_EVEN; ноль проверяет нижнюю границу суммы. |
| `calculatesAmountBeforeRoundingDisplayedRate` | TC-04 | Курс 1/3 и большая сумма обнаруживают раннее округление, которое примеры с точными курсами не выявляют. |

В `src/test/java/kz/su/currency/rates/ExchangeRateApiParserTest.java`:

| Метод | Ручной кейс | Почему создан |
| --- | --- | --- |
| `normalizesUsdQuotesToKztUnitsAndPreservesDates` | TC-05, TC-07 | Проверяет преобразование единиц за USD в KZT за единицу, точный разбор дробных чисел, UTC-дату timestamp, цифровой ISO-код и исключение CNH, отсутствующего в JDK. |
| `acceptsSnapshotWithoutRub` | Дополнение к TC-05 | Отсутствие RUB больше не является ошибкой: он не участвует в определении базы. |

Представители ошибок JSON, статуса, базы, даты, обязательных котировок, чисел и дублирующихся ключей проверяются здесь; HTTP 503 при сетевом сбое и сохранность таблицы проверяются вручную. |

В `src/test/java/kz/su/currency/rates/RateSchemaTest.java`:

| Метод | Что проверяет |
| --- | --- |
| `createsKztSchemaAndPreservesRatesOnRepeatedInitialization` | Новая H2-схема, чтение/запись KZT через репозиторий, запрет нулевого/null-курса и сохранность при повторной инициализации. |
| `migratesRubCacheToKztWithoutChangingDatesOrRebasingTwice` | Реальный пересчёт USD, RUB и KZT, сохранение дат и ISO-кодов, удаление старой колонки и идемпотентность. |
| `invalidatesLegacyCacheWithoutKztSoItCanBeReloaded` | Старый кеш без котировки KZT очищается; новая схема допускает последующую загрузку. |

У каждого `@Test` в исходнике есть комментарий с ID связанного ручного кейса либо обоснованием дополнительной проверки. Несколько связанных примеров внутри одного теста проверяют одно правило; `assertAll` показывает все нарушения этого правила за один запуск.

## Границы проверки

Для тестируемости расчёт выделен из `ConversionService` в `ConversionCalculator`, а `CurrencyResolver` отделён от HTTP-ошибок. Сервис использует эти же классы в реальных запросах; формулы и REST-контракт сохранены.

HTTP-загрузка, обновление кеша, отображение ошибок в REST и транзакции проверяются вручную в TC-05—12. Полный перебор ошибок JSON, измерение таймаутов, конкурентная нагрузка и несколько экземпляров не входят в этот минимальный набор. При изменении соответствующего участка набор следует расширить адресно.
